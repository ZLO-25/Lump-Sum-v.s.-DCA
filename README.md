# 📈 單筆投入 vs 定期定額（Lump Sum vs DCA）

用真實歷史資料回測「一次全部買進」和「分批慢慢買進」的差別，附勝率分析、資產配置壓力測試、波動統計、看盤牆，以及一整頁的觀念教學。

🔗 網站：<https://zlo-25.github.io/Lump-Sum-v.s.-DCA/>

## 功能

| 分頁 | 回答的問題 |
|---|---|
| 📈 單筆 vs 定期定額 | 從某一天開始，一次買和分批買，誰的期末資產多？為什麼？ |
| 🎲 勝率分析 | 把過去每個月都當起點，單筆投入贏的機率有多高？ |
| 💼 資產配置 | 股債配置 + 再平衡 + 退休提領，資金撐得住嗎？ |
| ⚡ 波動與風險 | 大漲大跌頻率、最長連漲連跌、最大回撤、索提諾比率 |
| 🖥️ 看盤牆 | 多格 TradingView 圖表自動輪播 |
| 📚 觀念教室 | 公平比較的規則、平均成本迷思、怎麼選，以及闕又上老師的投資心法與「每年買在最高點 vs 最低點」小實驗 |

設定好的回測可以直接複製網址分享，對方打開就會看到同樣的結果。

## 架構：為什麼不需要伺服器

舊版是 Streamlit（Python 伺服器跑在 GCP Cloud Run），每次按按鈕都由伺服器即時呼叫 yfinance。GitHub Pages 只能放靜態檔案，所以改成「先把資料準備好，計算交給瀏覽器」：

```
舊版（GCP Cloud Run）
  瀏覽器 ──按鈕──▶ Streamlit 伺服器 ──▶ yfinance ──▶ Yahoo
         ◀──畫面──  (Python 計算)

新版（GitHub Pages）
  ┌─────────── 每個平日 06:30（台灣時間）───────────┐
  │ GitHub Actions                                  │
  │   1. npm test           確認計算邏輯沒壞         │
  │   2. fetch_data.py      yfinance → data/*.json  │
  │   3. 部署到 GitHub Pages                        │
  └─────────────────────────────────────────────────┘
                         │
  瀏覽器 ──▶ 下載 index.html + data/*.json
         └─▶ engine.js 在瀏覽器裡計算、Plotly 畫圖
```

| 檔案 | 用途 |
|---|---|
| `index.html`、`assets/css/style.css` | 頁面與樣式 |
| `assets/js/engine.js` | **所有計算邏輯**（純函式，可單獨測試） |
| `assets/js/app.js` | 畫面互動、圖表 |
| `assets/vendor/` | 圖表函式庫 Plotly（放在 repo 內自行託管，不依賴外部 CDN） |
| `scripts/tickers.json` | 要下載哪些標的 |
| `scripts/fetch_data.py` | 下載價格存成 JSON |
| `tests/engine.test.mjs` | 計算邏輯的單元測試 |
| `.github/workflows/deploy.yml` | 自動更新資料並部署 |
| `legacy-streamlit/` | 舊版程式碼（僅供參考，已不使用） |

## 新增標的

### 方法一：在網站上編輯（需要密碼）

網站右上角「⚙️ 管理標的」→ 輸入密碼 → 新增 / 刪除標的或群組 → 「儲存並重新部署」，約 2 分鐘後生效，所有人都看得到。

```
第一次使用（只做一次）
  建立 GitHub Fine-grained Token（只授權這個 repo，Contents: Read and write）
        │
        ▼
  網站「⚙️ 管理標的」貼上 Token + 設定密碼
        │  Token 用密碼加密（PBKDF2 60 萬次 + AES-256-GCM）
        ▼
  config/admin-key.json（存在 repo，公開但沒有密碼看不懂）

之後每次編輯
  輸入密碼 → 解密出 Token（只在記憶體）→ GitHub API 更新 scripts/tickers.json
        → 觸發 GitHub Actions → 抓新標的價格 → 重新部署
```

安全性取捨：加密檔是公開的，有心人可以離線一直猜密碼，所以**密碼越長越安全**；Token 只授權這個 repo 的內容寫入，最壞情況是有人改了這個網站，不會影響你其他帳號資料。忘記密碼或 Token 過期：刪除 `config/admin-key.json` 後重新設定。

### 方法二：直接改檔案


編輯 `scripts/tickers.json`，在任一群組加一行（代號用 Yahoo Finance 的寫法，例如台股 `2412.TW`）：

```json
{"symbol": "2412.TW", "name": "中華電", "note": "新台幣計價"}
```

push 到 main 後，GitHub Actions 會自動抓資料並重新部署（約 2 分鐘），新標的就會出現在網站的下拉選單裡。不想改程式的話，也可以在網站右上角「📂 上傳 CSV」（需要 `Date` 和 `Close` 或 `Adj Close` 欄位，例如從 Yahoo Finance 下載的歷史資料）。

## 計算方式（與舊版的差異）

```
DCA 每日總資產 = 未投入現金 × (1 + 現金利率)^(天數/365) + 累積股數 × 當日還原收盤價
單筆每日總資產 = (總金額 ÷ 第一天價格) × 當日還原收盤價
總報酬率 = 期末 ÷ 總金額 − 1          （兩種策略同一個分母）
CAGR     = (期末 ÷ 總金額)^(1/年數) − 1
```

這次改版修正 / 新增的地方：

1. **DCA 扣款間隔修正**：舊版用 `pd.date_range(開始, 開始+12個月, periods=12)`，最後一筆落在第 12 個月，間隔變成 12/11 ≈ 1.09 個月。新版第 k 筆在第 k × (月數/次數) 個月，「12 個月分 12 次」就是每月同一天扣款。
2. **資產配置的年度標的報酬**：舊版從「每年第一個交易日收盤」起算，漏掉了第一天的漲跌；新版改從「上一年最後收盤」起算。
3. **有提領時的年化報酬**：舊版用「期末餘額 ÷ 期初」，提領越多年化越低，誤把提領當虧損。新版改用時間加權報酬（TWR）。
4. **索提諾比率**：改用標準的下檔標準差（所有日子都算，正報酬視為 0）；年化時依資料自動判斷每年交易日數（股票約 252、加密貨幣約 365）。
5. **提醒實際起點**：選了 1929 年但標的 1993 年才上市時，舊版會默默從 1993 開始；新版會明確提示。
6. **新增**：現金利率選項、DCA 平均成本 vs 平均價格、平均持股比例、滾動勝率分析、提領通膨調整、混合幣別警告。

## 台股資料校正（分割 / 配股）

台股單日漲跌幅有上限（2015/6 前 ±7%，之後 ±10%），所以 Yahoo 資料裡單日超過 ±25% 的跳動一定不是真的漲跌，而是「分割 / 配股」的還原出錯。`scripts/fetch_data.py` 會逐一判斷：

```
跳動比例 j = 當天價格 ÷ 前一天價格，修正 = 斷層前價格整段 × f

  前後 3 個交易日有分割/配股事件（比例 r）？
    ├─ j ≈ 1/r → 事件沒有往前還原        → f = 1/r
    └─ j ≈ r   → 事件被反方向還原         → f = r
  沒有事件，但 j ≈ 1/N（整數，誤差 ≤ 3%）？
    └─ 之後的 1 拆 N 只還原到一半        → f = 1/N
  都不是 → 資料斷層，無從得知真實漲跌    → f = j（當天報酬視為 0）

  檢查：修正後當天報酬必須落在當時的漲跌幅限制內
```

用分割比例修正、而不是一律把當天報酬抹成 0，才能保留當天真實的漲跌。2026-11 用原始收盤價與 Yahoo 分割事件逐一確認的結果：

| 標的 | 日期 | Yahoo 跳動 | 原因 | 修正 |
|---|---|---|---|---|
| 0050 | 2014-01-02 | −75.1% | 2025 年 1 拆 4，Yahoo 只還原到 2014 年（事件清單也沒有這筆） | 之前 ÷4，當天 −0.26% |
| 00631L | 2015-01-05 | −95.4% | 比例剛好 1/22，與 1 拆 22 分割吻合，同樣只還原到 2015 年 | 之前 ÷22，當天 +0.37% |
| 00631L | 2015-08-24 | −33.6% | 無事件、非整數比例 | 資料斷層，當天視為 0 |
| 2317 | 1994-05-24 | +117.5% | 無事件 | 資料斷層，當天視為 0 |
| 2317 | 1995-08-16 | −27.2% | 配股 ×1.4 沒有往前還原 | 之前 ÷1.4，當天 +1.98% |
| 2317 | 2000-01-04 | −47.0% | 無事件、非整數比例 | 資料斷層，當天視為 0 |
| 2317 | 2000-07-17 | +35.0% | 配股 ×1.3 被反方向還原 | 之前 ×1.3，當天 +3.8% |
| 2454 | 2003-08-19 | +37.2% | 配股 ×1.35 被反方向還原 | 之前 ×1.35，當天 +1.6% |

美股、港股不做這個處理（例如 AAPL 2000-09-29 −52%、ETH 2020-03-12 −42% 都是真的暴跌），它們的分割 Yahoo 都有正確還原。想重新檢查：GitHub → Actions →「診斷價格跳動」→ Run workflow，會列出每個跳動前後的原始價、還原價與分割/配股事件（`scripts/diagnose_breaks.py`）。

## 本機開發

```bash
# 1. 下載價格資料（需要網路）
pip install -r scripts/requirements.txt
python scripts/fetch_data.py

# 2. 啟動本機伺服器（直接雙擊 index.html 會因為瀏覽器安全限制讀不到 JSON）
python -m http.server 8000
# 打開 http://localhost:8000

# 3. 跑測試
npm test
```

## 部署設定（第一次）

Repository → **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。之後每次 push 到 main 或每個平日早上都會自動部署。
